# Warehouse Management System - Product Requirements Document

## 1. Product Overview

The Warehouse Management System (WMS) is a comprehensive solution designed to streamline and optimize warehouse operations for agricultural supply businesses. The system manages inventory, tracks products across warehouse sections, processes orders, handles incoming and outgoing deliveries, and monitors employee attendance.

## 2. System Architecture

The application is built using the Laravel PHP framework with a Model-View-Controller (MVC) architecture. It uses:
- Laravel's Eloquent ORM for database interactions
- Blade templating engine for views
- Authorization policies for access control
- Route middleware for authentication

## 3. Core Modules

### 3.1 User Management

**Purpose:** Manages system users with different roles and permissions.

**Key Features:**
- User registration and authentication
- Role-based access control (employee, admin, etc.)
- Employee management with internal ID tracking
- User suspension capabilities

**Data Model:**
- Users have attributes including internal_id, names, email, phone, role assignments, and password
- System differentiates between system roles (admin, employee) and employee roles (specific job functions)

### 3.2 Warehouse Management

**Purpose:** Organizes and tracks physical storage locations.

**Key Features:**
- Warehouse registration and configuration
- Warehouse sectioning for organized storage
- Product-to-section mapping

**Data Model:**
- Warehouses have multiple sections
- Sections can contain multiple products
- Products can be stored across multiple warehouse sections

### 3.3 Inventory Management

**Purpose:** Tracks all products and their quantities in the system.

**Key Features:**
- Product registration with unique internal IDs
- Stock quantity tracking
- Category organization
- Price calculation including overhead and profit margins

**Data Model:**
- Products have categories, stock quantities, and pricing information
- Products maintain overhead costs and profit margins
- Products can be suspended (made inactive)

### 3.4 Order Processing

**Purpose:** Handles customer orders and order fulfillment.

**Key Features:**
- Order creation (both walk-in and pre-registered customers)
- Order item management
- Order status tracking
- Receipt generation
- Order delivery scheduling

**Data Model:**
- Orders contain multiple order items
- Orders track status through the fulfillment process
- Receipts are generated for completed orders

### 3.5 Delivery Management

**Purpose:** Manages both incoming deliveries (from suppliers) and outgoing deliveries (to customers).

**Key Features:**
- Incoming delivery registration and tracking
- Delivery success/cancellation handling
- Batch processing for deliveries
- Proof of delivery management

**Data Model:**
- Incoming deliveries track expected products and quantities
- Delivery records maintain status (pending, successful, cancelled)
- Deliveries can be processed individually or in batches

### 3.6 Employee Attendance

**Purpose:** Tracks employee time-in and time-out records.

**Key Features:**
- Attendance record creation
- Time-in and time-out tracking
- Attendance status monitoring (present, finished duty, no timeout)
- Attendance reporting with time calculation

**Data Model:**
- Attendance records link to employee user accounts
- Records store date, in_time, and out_time
- System calculates work duration from timestamps

## 4. User Roles and Permissions

The system implements role-based access control with the following primary roles:

1. **Admin:** Full system access including user management
2. **Employee:** Limited access based on assigned employee role
3. **Warehouse Manager:** Access to warehouse and inventory management
4. **Order Processor:** Access to create and manage orders

## 5. Business Rules

1. Product prices are calculated by combining base cost and profit margin
2. Employee attendance status is determined by comparing record date with current date and timeout status
3. Orders follow a defined workflow from creation to delivery
4. Product internal IDs follow a specific format with collision prevention
5. Warehouse sections organize products for efficient storage and retrieval
